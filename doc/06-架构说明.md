# 架构说明

这份文档讲 `win/` 这份代码由哪些部分组成、一次请求怎么流动、WARP 池如何管理，以及进程生命周期由谁保证。它描述的是**当前仓库的实际实现**，不是上游宣传页。

## 1. 定位

`win/` 是主仓库 `jasonxu114514/opencode2api` 的 Windows 二次开发副本：

- 基线：上游 `2bf547c`，2026-11-01 合并 `v1.4.6`（`58f5667`）
- 额外内容：WARP 物理网卡绑定、出口池惩罚模型、启动降级与后台重试、进程树 Job Object 约束、warpprobe 工具
- 运行形态：单个 `opencode2api.exe`，静态链接，不需要 Go 环境和 DLL
- 对外协议：OpenAI 兼容 HTTP API（`/v1`）+ 管理 WebUI

上游代码负责模型目录、协议转换、鉴权和轮换；Windows 侧改动集中在 `internal/warp/`、`internal/gateway/{warp,refresh,runtime}.go` 和启动脚本。

## 2. 进程与端口

| 组件 | 进程 | 端口 | 作用 |
|---|---|---|---|
| 网关 | `opencode2api.exe` | `127.0.0.1:28080` | OpenAI 兼容 API、`/healthz` |
| 管理界面 | 同一个进程 | `127.0.0.1:28081` | 配置、日志、模型、WARP 状态 |
| 边缘代理（可选） | `tools\edgeproxy.exe` | `127.0.0.1:29090` | 给注册通道和 `proxies` 提供本地出口 |
| WARP | 网关进程内 | 无监听 | 用户态 WireGuard + gvisor netstack |

边缘代理不是必需组件：`tools\edgeproxy.exe` 不存在时 `start-supervised.ps1` 会跳过它，配置里的 `http://127.0.0.1:29090` 只会作为不可用代理被健康检查剔除，请求回落到 `direct`。

## 4. 一次请求的路径

```text
客户端
  │  POST /v1/chat/completions
  ▼
网关 HTTP 层（鉴权、请求体解析、请求账本）
  │
  ├─ 有 Key / 官方通道 ──► 上游 opencode.ai（按 Key 计费）
  │
  └─ 匿名免费档
       │
       ├─ WARP 可用 ──► 从池里租一个出口（/64）
       │                   │
       │                   ▼
       │                进程内 netstack ──► WARP endpoint ──► opencode.ai
       │
       └─ WARP 不可用 / 429 / 403 / 5xx
                           │
                           ▼
                       proxies 列表（edgeproxy、direct、外部代理）
```

关键行为：

1. **匿名档优先 WARP**，只有 WARP 建不出出口、返回额度/限速/5xx 或流中断时才回退 `proxies`。
2. **确定性 4xx 不回退**：请求本身错误（太长、格式错）原样返回，避免重复打上游。
3. **流式请求**有 2 分钟空闲看门狗；连续无字节就关闭 body、标记出口失败，让客户端重试。
4. **重试**默认最多 3 次；每次失败会观测状态码与响应体，决定是换出口还是直接返回。
5. **429 是上游透传**，不是网关限流；按出口 `/64` 计额度。

## 5. WARP 池

### 5.1 组成

```text
Pool
  active    map[id]*exit     在环里的出口
  reserved  map[egress]bool  正在注册、占位的 /64
  cooling   map[egress]time  冷却截止时间（持久化）
  strikes   map[egress]int   额度命中次数（持久化）
```

一个"出口"（`exit`）包含：一个 WARP 设备、一条进程内 netstack、一个公网 IPv6 `/64`。同一 `/64` 在池内只允许一个出口，因为免费额度按 `/64` 计算。

### 5.2 生命周期

```text
启动
  └─ 同步注册第 1 个出口（受 warpStartupDeadline 约束）
       └─ 成功后返回，后台继续预热到 preloadFor(size)
            pool_size ≤ 8 时全部预热；> 8 时先预热 8 个

请求
  └─ Acquire：取空闲出口，没有就等
       ├─ 25 秒内仍无出口 → ErrNoExit（503 warp_unavailable）
       └─ 拿到租约 → 发请求

结果
  ├─ 2xx        → 清空该 /64 的 strikes
  ├─ 403/429    → 分类：额度（默认）或普通限速；出口退役
  ├─ 传输失败    → 出口退役，90 秒后可复用
  └─ 其他       → 原样返回，不换出口
```

### 5.3 惩罚模型（2026-11-01 起）

| 类型 | 判定 | 冷却 | 替换失败时能否复活 |
|---|---|---|---|
| 额度 | 403/429 且响应体无明确限速标记；默认兜底 | 30m → 2h → 8h → 24h，`Retry-After` 更长时优先 | **不能** |
| 普通限速 | 响应体含 `rate_limit` / `too many requests` 等 | 1 分钟起，最长 5 分钟 | **不能** |
| 传输 | 超时、EOF、握手失败 | 90 秒 | 能（池空时） |

`replace()` 只有在出口是传输失败时才允许在注册失败后放回 `active`。这一条消除了旧版本的死循环：池空 → 复活刚被 429 的 `/64` → 再 429。

### 5.4 持久化

`config.json.warp-state.json`：

```json
{
  "cooling": { "2a09:bac1:1980:120::/64": "2026-11-01T14:30:00Z" },
  "strikes": { "2a09:bac1:1980:120::/64": 2 }
}
```

写入是原子替换（临时文件 + rename），文件权限 `0600`。写不进去时日志会输出告警，但不会阻塞请求；此时重启会丢失冷却记忆。冷却记录按 `/64` 去重，不含密钥、令牌或设备凭据。

## 6. 进程生命周期

`start-supervised.ps1` 创建 Windows Job Object，设置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，把自身、网关和边缘代理都放进同一个 Job：

```text
控制台窗口关闭 / Ctrl+C / 直接结束 PowerShell
  └─ 最后一个 Job 句柄关闭
       └─ 内核终止 Job 内全部进程（网关 + 边缘代理）
```

因此不存在"窗口关了但 `edgeproxy.exe` 还在监听 29090"的残留。后台模式 `start-background.ps1` 则用 `logs\pid.txt` 记录 PID，由 `stop-opencode2api.ps1` 按 PID 或可执行文件绝对路径清理。

WARP 在进程内完成，不建网卡、不改路由、不改 DNS、不碰防火墙；进程退出后网络参数与启动前一致。

## 7. 状态文件

| 文件 | 生产者 | 是否可删 | 说明 |
|---|---|---|---|
| `config.json` | 人工/WebUI | **不可删** | 运行配置，含 Key 和密码哈希 |
| `config.json.bak` | 配置保存 | 可删 | 上一次保存的副本 |
| `config.json.warp-state.json` | WARP 池 | 可删 | 删除后忘记冷却与 strikes，会重新注册 |
| `config.json.models.catalog.json` | 模型刷新 | 可删 | 断网时的兜底目录 |
| `config.json.<hash>.availability.json` | 能力探测 | 可删 | 模型能力缓存 |
| `config.json.rotation.json` | 轮换组 | 可删 | 轮换状态 |
| `logs\*` | 网关/脚本 | 可删 | 日志与 PID |
