# 配置参考

配置来自 `config.json`，启动时用 `-config` 指定。解析是严格的：未知字段、第一个 JSON 值之后的内容都会报错。文件支持 `//` 和 `/* */` 注释，也支持尾逗号。

当前这份配置的关键项（本次实测）：

```json
{
  "listen": "127.0.0.1:28080",
  "server_keys": ["sk-local-test"],
  "anonymous": true,
  "warp": { "enabled": true, "pool_size": 4, "stack": "ipv6" },
  "proxies": ["direct"],
  "retry": { "max_attempts": 3, "timeout_seconds": 300 },
  "models": { "refresh_seconds": 300, "free_only": false },
  "webui": { "enabled": true, "listen": "127.0.0.1:28081", "username": "admin" }
}
```

---

## 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `listen` | string | API 监听地址，必填，不能为空 |
| `server_keys` | string[] | 客户端访问网关用的本地 Key |
| `server_key_metadata` | object | 每个 Key 的附加信息（可选） |
| `zen_keys` | string[] | Zen 付费档的上游 Key |
| `go_keys` | string[] | Go 订阅档的上游 Key |
| `anonymous` | bool | 开启无 Key 的免费档 |
| `prefer` | `zen` / `go` | 两个付费档都能服务同一模型时，先试哪个 |
| `proxies` | string[] | 出站代理列表，`direct` 表示直连 |
| `proxyfile` | string | 从文件追加代理（只在运行时合并，不会写回配置） |
| `warp` | object | WARP 出站，见下文 |
| `upstream` | object | 三个上游地址，一般不用改 |
| `retry` | object | 重试预算 |
| `models` | object | 模型发现 |
| `performance` | object | 连接池与超时 |
| `logging` | object | 日志 |
| `webui` | object | 管理界面 |
| `rotation` | object | 模型轮换组 |
| `reasoning` | object | 强制思考等级 |

---

## `warp`

```go
// 开启后，免费模型流量（匿名档 + Zen Key 的免费兜底）
// 走用户态 WireGuard 隧道，而不是任何配置的代理。
```

| 字段 | 说明 |
|---|---|
| `enabled` | 是否启用。启动时最多等 60 秒建出口，失败则**降级为不启用**继续监听，并在后台自动重试（详见 `doc/03`） |
| `pool_size` | 保持多少个已注册出口，1–32，0 取默认 4；不超过 8 时全部预热，超过 8 的部分按并发扩容 |
| `stack` | 隧道地址族：`ipv4` / `ipv6`（默认） |
| `source_ipv6` | 外层 IPv6 前缀（通常是一个路由到你机器的 /64），每个出口绑定它来换公网地址 |

关于 `source_ipv6`：

- 必须是 IPv6 前缀，`/64` 或更短，且要求 `stack` 为 `ipv6`
- 作用是通过轮换源地址让替换出口拿到新的公网出口；不配的话多个出口共用一个地址，按出口计的免费额度不会重置
- **Linux 之外是空操作**（`internal/warp/freebind_other.go`），Windows 上填了也不会生效

WARP 和 `proxies` 在免费模型上是互斥的：开了 WARP 就不会用代理。

---

## `proxies`

```json
"proxies": ["direct", "http://127.0.0.1:10810", "socks5://user:pass@host:port"]
```

- `direct` 表示不走代理
- 一个代理 = 一个出口；项目只对内置 WARP 的 /64 做去重，对外部代理不做
- 代理健康检查是硬编码的 `https://cloudflare.com/cdn-cgi/trace`，超时 10 秒（`internal/gateway/refresh.go`）。这个地址不通会把代理判为不可用，进而拖垮免费档

---

## `retry`

| 字段 | 说明 |
|---|---|
| `max_attempts` | 重试循环的尝试上限。匿名档下它是"最多抽多少个轮换代理"的下限 |
| `timeout_seconds` | 整个客户端请求（含所有重试）的总超时 |

---

## `models`

| 字段 | 说明 |
|---|---|
| `refresh_seconds` | 模型目录刷新间隔，当前 300 |
| `protocols` | 指定某个模型用哪种上游协议，覆盖目录里的报告值 |
| `free_only` | 只发现和路由免费模型，即使配了付费 Key |
| `anonymous_backoff` | 无 Key 档的熔断器：连续失败 `threshold` 次后暂停 `base_hours` 小时，每次再触发翻倍，上限 `max_hours` |

`anonymous_backoff` 三个字段的默认值：`threshold=6`、`base_hours=1`、`max_hours=24`。不写这个块就完全不熔断。

---

## `performance`

| 字段 | 当前值 | 说明 |
|---|---|---|
| `max_idle_conns` | 2048 | 全局空闲连接上限 |
| `max_idle_conns_per_host` | 256 | 单主机空闲连接上限 |
| `max_conns_per_host` | 0 | 单主机总连接上限，0 = 不限 |
| `idle_conn_timeout_seconds` | 120 | 空闲连接回收时间 |
| `connect_timeout_seconds` | 5 | 拨号超时 |
| `failure_cooldown_seconds` | 15 | Key 或代理失败后的基础冷却 |
| `attempt_timeout_seconds` | 0 | 单次尝试上限；0 表示只用请求级超时 |
| `first_event_timeout_seconds` | 0 | 等首字节的上限；0 表示不等 |
| `max_anonymous_exits` | 0 | 一次请求最多走几个静态代理出口；0 用内置上限 |
| `free_tier_block_seconds` | 0 | 被免费档标记为滥用的出口冷却多久；0 用内置的 15 分钟 |

`attempt_timeout_seconds` 值得注意：大于 0 时它会作为共享 transport 的响应头等待时间，同时给每次推理尝试挂上 context deadline，避免一个卡死的出口吃光整个请求预算。当前为 0，所以只受 `retry.timeout_seconds=300` 约束。

## `logging`

| 字段 | 说明 |
|---|---|
| `level` | `debug` / `info` / `warn` / `error` |
| `ring_size` | WebUI 里保留的内存日志条数，当前 2000 |
| `dump_request_bodies` | 打印发往上游的原始请求体（已脱敏、有长度上限）。默认关闭，因为里面有对话内容 |

排查翻译/重试问题时把 `dump_request_bodies` 打开最有效。

## `webui`

| 字段 | 说明 |
|---|---|
| `enabled` | 关闭时完全不校验密码，也不开端口 |
| `listen` | 监听地址 |
| `username` | 登录名 |
| `password` | **只用于设置密码的明文**，启动时被转成 Argon2id 哈希写回，随后清除 |
| `password_hash` | 实际使用的哈希 |
| `session_ttl_minutes` | 会话有效期，当前 720 分钟（12 小时） |

密码至少 10 个字符。`enabled` 和 `listen` 的改动只在重启后生效。

---

## `rotation`

两个轮换组，由 **Go 订阅档** 提供服务：

| 字段 | 说明 |
|---|---|
| `sota.alias` / `sota.order` | 组名和故障转移顺序。SOTA 组固定只能有这 5 个模型：`deepseek-v4.1-flash`、`glm-5.3`、`grok-4.6`、`kimi-k3`、`qwen3.8-max` |
| `sweet.alias` / `sweet.order` | 其余模型归入该组，顺序不写就由运行状态自动累积 |
| `first_output_seconds` | 一次尝试多久没产出首字就换下一个，1–300，默认 30 |

没有 `go_keys` 时这两个组没有上游可用，客户端请求 `sota` / `sweet` 会失败。当前配置没有配 Go Key。

---

## `reasoning`

| 字段 | 说明 |
|---|---|
| `effort` | 客户端没指定思考等级时用的默认值。除常规等级外，`none` 会把 reasoning 从请求里剥掉，`auto` 对 Zen 档的免费模型取探测到的最高可用等级 |
| `effort_by_model` | 按模型 ID 覆盖上面的默认值 |

客户端显式指定的等级永远优先（Anthropic 的 `output_config.effort`、Chat 的 `reasoning_effort`、Responses 的 `reasoning.effort`）。当前 `effort` 是 `max`。

---

## 上游地址

| 字段 | 默认值 | 用途 |
|---|---|---|
| `zen` | `https://opencode.ai/zen` | Zen 付费档，v1 请求格式 |
| `go` | `https://opencode.ai/zen/go` | Go 订阅档，v2 请求格式 |
| `anonymous` | `https://opencode.ai/inference` | 免费档的唯一入口 |

网关按 base URL 判断请求格式：以 `/zen` 结尾走 v1，其它走 v2。
