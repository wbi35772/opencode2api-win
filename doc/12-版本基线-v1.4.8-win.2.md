## 3. 免费道三层问题（win.1 结论，仍然有效）

### 3.1 第一层：旧二进制还在发 `clint_`

| 项 | 事实 |
|---|---|
| 现象 | 带 tools 的真实会话必 429；极简请求有时 200 |
| 原因 | 旧 exe 早于 #182，工具名仍是 `clint_`；上游免费层对 `clint_` 直接返回 `FreeUsageLimitError` |
| 证据 | 旧 exe 二进制内含 `clint_`；新 exe `clint_=False`、`mcp_=True` |
| 处理 | 部署 v1.4.8 构建 |

### 3.2 第二层：WARP 出口状态里全是已烧掉的 `/64`

| 项 | 事实 |
|---|---|
| 现象 | 换新 exe 后仍然 429，`/healthz` 显示 `active` 很少、`cooling` 一堆 |
| 原因 | `config.json.warp-state.json` 继承了 13–14 个已耗尽出口 |
| 处理 | 停进程 → 备份状态文件 → 删除 → 重启，重新注册新出口 |
| 备份 | `config.json.warp-state.json.bak-20261116-223051` |

### 3.3 第三层：池容量与出口冷却参数太小

| 参数 | 旧值 | 新值 | 作用 |
|---|---:|---:|---|
| `warp.pool_size` | 16 | 32 | 保持更多已注册出口 |
| `performance.max_anonymous_exits` | 0（内置 8） | 32 | 一次请求最多可抽的静态代理出口数 |
| `performance.free_tier_block_seconds` | 0（内置 900s） | 120s | 被免费层标记的出口更快回到轮换 |

> 配置备份：`config.json.bak-20261116-222128`。`warp.pool_size` 上限 32；实际预热受 `preload` 上限 12 约束，池子按需扩容。

### 3.4 win.1 实测证据

| 场景 | 结果 |
|---|---|
| 极简请求（无 tools） | `200` / 28.6s / `PONG` |
| 带 tools 非流式 | `200` / 35.1s / `PONG`，usage 5859 |
| 带 tools 流式（SSE） | `200` / 8.0s，`role` → `delta.content: "PONG"` → `stop` |
| 池子里只有 1 个出口时同一 SSE 请求 | `429` / 96s（对照） |
| 池子长到 4+ 个新出口后同一 SSE 请求 | `200` / 8.0s |

**结论**：流式/参数不是问题；问题是出口额度与工具名前缀。免费配额按「project × 出口」烧，一次成功请求会消耗一个出口；池子补充速度约 30–40 秒 1 个。

## 4. 请求路径与 WARP 池

```text
客户端 (OpenCode / curl)
   │  Authorization: Bearer sk-win-local-test
   ▼
opencode2api :28080
   │  1. 本地鉴权、请求翻译、tools → mcp_ / official 别名
   │  2. 选层：Zen Key / Go Key / Anonymous
   ▼
匿名层 (anonymous=true)
   │  3. 选出口：WARP pool（每个 /64 一个租约）
   │     429 → retire 出口 + RotateIDs(session)
   │     若 FreeUsageLimitError → RotateProject（配额按 project × 出口）
   ▼
OpenCode 上游 /inference
   │  4. 返回 200 / SSE / 429；非诊断请求写入被动可用性
   ▼
客户端
```

### 4.1 池状态曲线（win.1 实测，win.2 同参数）

| 时间 t | active | cooling | 说明 |
|---:|---:|---:|---|
| 0s | 0 | 4 | 刚重启，WARP 未就绪 |
| 40s | 0 | 3 | 后台注册中 |
| 80s | 1 | 2 | 第一个新出口可用 |
| 120s | 2 | 2 | 池子开始回血 |
| 160s | 4 | 2 | 可承接连续请求 |
| 200s | 4 | 2 | 稳定 |

### 4.2 两个必须知道的判定

- `/healthz` 的 `warp.cooling` 是历史冷却记录数，不代表当前出口都不可用；看 `active` / `standby` 更直接。
- 如果 `warp.status=unavailable` 且 `active=0`，先看本机代理/WARP 依赖，不要直接判定二进制坏了。

## 8. 已知问题与限制

1. **WARP 依赖本机 Clash 7897 的 TCP + UDP。** 如果 `curl -x socks5h://127.0.0.1:7897` 超时，WARP 注册/握手会失败，日志出现 `handshake=never rx=0`；后台会自动重试，恢复后无需重启。
2. **免费额度不是无限。** 上游按 `project × 出口` 计；连续请求会快速消耗出口。`cooling` 增长是正常现象，等池子回血或重置状态文件。
3. **`warp-state.json` 会持久化 spent 出口。** 换机/长时间不用后如果持续 429，按 7.3 重置。
4. **Go OAuth 只是配置占位。** `go_subscription` 字段存在，但没有完整 Device OAuth 流程；没有 `go_keys` 时 `sota`/`sweet` 组不可用。
5. **`#167` 未移植。** Playground 诊断页不能把一次生成固定到单个 relay；真实会话不受影响。
6. **未移植 `0d05fe93`。** 该提交在 v1.4.8 之后、尚未发版，包含“匿名默认关闭”和批量代理管理；升级到它之前要重新评估匿名通道策略。
7. **`listen` 当前是 `0.0.0.0`。** 如果不需要局域网访问，建议改回 `127.0.0.1` 并重启；WebUI 仍只监听回环。
8. **发布提交。** 代码提交 `758cb59`；文档提交随 tag `v1.4.8-win.2`；发布包与该 tag 对应。
