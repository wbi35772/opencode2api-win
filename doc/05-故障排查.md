# 故障排查

按现象查，每条都是实际遇到过的。

---

## 双击 bat / ps1 后端口没监听，或只监听了但 WARP 没起来

**原因**：`config.json` 里 `warp.enabled=true`，但 WARP 建不出出口。

**现在的行为**：启动时最多等 60 秒，失败就以"WARP 未启用"继续启动，28080/28081 照常监听，随后在后台按 15s→30s→1m→2m→5m 自动重试，成功后热切换回 WARP，不用重启。

**日志特征**（`logs\console.log`）：

```text
WARP egress unavailable; starting without it            event=warp_startup_fallback
initialize WARP egress: verify WARP ipv6 egress:
Get "https://[2606:4700:4700::1111]/cdn-cgi/trace": context deadline exceeded
```

稍后恢复时会出现：

```text
WARP egress recovered in the background
```

**判断 WARP 能不能用的标准**（不是 1.1.1.1）：

1. 本机能不能连上 `https://api.cloudflareclient.com/v0i1909051800/reg` —— 通通常返回 `404` 或 `400`，超时/`000` 就是不通
2. 到 WARP endpoint 的 UDP 2408 通不通（`162.159.192.x`）

`1.1.1.1` 只用于在**隧道内部**验证，本机连不上它不影响 WARP。

**处理**：

1. 先确认上面两条依赖；`api.cloudflareclient.com` 超时说明 Cloudflare 整段不可达，等它恢复，后台重试会自己接上
2. TUN 模式已经不影响 WARP（出站钉在物理网卡上），不需要再关 TUN；只有"物理网卡到不了 Cloudflare、只有 TUN 能到"时才用 `set OPENCODE2API_WARP_NO_PIN=1` 启动
3. 想彻底不用 WARP，把 `warp.enabled` 改成 `false`，重启

```powershell
$p='config.json'; $j=Get-Content $p -Raw | ConvertFrom-Json
$j.warp.enabled=$false
[IO.File]::WriteAllText($p, ($j | ConvertTo-Json -Depth 20), (New-Object System.Text.UTF8Encoding($false)))
```

## `/healthz` 能通，但 `ready:false` 或 `status:degraded`

不是同一种问题，看 `issues` 数组：

| issues | 含义 | 影响 |
|---|---|---|
| `model_catalog_stale` | 模型目录超过 600 秒没刷新 | 只影响元数据，模型和对话照常 |
| `no_healthy_proxies` | 代理全部不可用 | 免费档不可用 |
| `free_tier_lane_paused` | 匿名档被熔断（连续失败） | 免费请求被拒，需要等或重启 |

`models.opencode.ai` 直连很慢（实测平均 6.8 秒），容易超时导致 stale。开 WARP 后这个问题消失。

## 429 `Free usage limit reached`

```json
{"error":{"message":"Free usage limit reached. Free models work in OpenCode ...","type":"upstream_error"}}
```

**先分层判断，不要直接归因“额度用完”。** 2026-11-17 遇到的是三层叠加：

| 层 | 现象 | 确认 | 处理 |
|---|---|---|---|
| 1. 二进制/工具前缀 | 带 tools 的真实会话必 429，极简请求有时 200 | `healthz.version` 不是 `v1.4.8-win.1`，或旧二进制仍发 `clint_` | 换 v1.4.8+ 构建（`mcp_` 前缀）；见 `doc/12` |
| 2. 匿名免费额度 | 极简也 429，响应带 `Retry-After: 60` | `/healthz` 里 `keys.zen=0`、`keys.go=0`、`anonymous=true` | 免费配额按 **(project, 出口 /64)** 计；等冷却或换出口，换 session 不换出口仍会 429 |
| 3. 出口池空 | 请求前 `warp.active=0`，`cooling` 很多 | `curl /healthz` 看 `warp` | 等 2–4 分钟池子回血；必要时按下面步骤重置 WARP 状态 |

先确认版本和池状态：

```powershell
(Get-FileHash .\opencode2api.exe -Algorithm SHA256).Hash
curl.exe --noproxy "*" http://127.0.0.1:28080/healthz
```

期望看到 `version: v1.4.8-win.1`、`ready: true`，以及 `warp.status: ready`。`active=0` 且 `cooling` 持续增加时，先把本机 Clash 的 `127.0.0.1:7897`（TCP + UDP）恢复，再等后台重试；WARP 起不来不会阻止 28080 监听。

只有“所有出口都被免费层标记、等待也无法恢复”时才重置状态文件（会丢掉已有的冷却记忆）：

```powershell
.\stop-opencode2api.ps1
Copy-Item config.json.warp-state.json "config.json.warp-state.json.bak-$(Get-Date -Format yyyyMMdd-HHmmss)" -Force
Remove-Item config.json.warp-state.json -Force
.\start-background.ps1
```

重置后池子从 0 开始注册，通常 20–120 秒恢复 `warp.ready`；刚恢复时 `active=1`，连续请求仍可能 429，等 `active≥3` 再压测。

## 登录 WebUI 401

密码被改过。`config.json` 里的 `password_hash` 对不上任何已知密码时，用明文 `password` 字段重置：

```powershell
$p='config.json'; $j=Get-Content $p -Raw | ConvertFrom-Json
$j.webui.PSObject.Properties.Remove('password_hash')
$j.webui | Add-Member -NotePropertyName password -NotePropertyValue 'win-admin-2026' -Force
[IO.File]::WriteAllText($p, ($j | ConvertTo-Json -Depth 20), (New-Object System.Text.UTF8Encoding($false)))
```

重启后明文会被转成 Argon2id 哈希写回，`password` 字段自动消失。密码至少 10 个字符。

**注意**：`config.json.bak` 是上一次保存的副本，别拿它当"原始配置"覆盖，里面的密码哈希可能也是旧的。

## 端口被占用

```text
listen tcp 127.0.0.1:28080: bind: An attempt was made to access a socket in a way forbidden by its access permissions
```

查谁占了：

```powershell
Get-NetTCPConnection -LocalPort 28080,28081 -State Listen | Select-Object LocalPort,OwningProcess
```

`start-background.ps1` 会先检查端口，被占用时直接报错，不会起两个实例。

## 后台启动脚本说 "did not become ready"

脚本以 API 端口有响应判定成功，`ready:false` 不算失败。如果连端口都没起来，先看：

```powershell
Get-Content logs\stderr.log -Tail 30
Get-Content logs\stdout.log -Tail 30
```

## 免费模型能用，但模型目录一直 stale

`models.opencode.ai` 走不通或太慢。开 WARP 通常能解决；也可以手动删缓存让下次重启重建：

```powershell
Remove-Item config.json.models.catalog.json -Force
```

## 想彻底回到干净状态

```powershell
.\stop-opencode2api.ps1
Remove-Item config.json.bak,config.json.models.catalog.json,config.json.*.availability.json,config.json.rotation.json -Force -ErrorAction SilentlyContinue
.\start-background.ps1
```

这些全是运行期缓存，删掉只会导致下次启动重新拉取。

## 排障时该看的日志事件

`logs\stdout.log` 是结构化 JSON，按 `event` 字段过滤最有效：

| event | 含义 |
|---|---|
| `server_started` | 监听成功 |
| `catalog_refreshed` | 模型目录刷新成功 |
| `anonymous_refresh_failed` | 免费档目录刷新失败 |
| `proxy_unavailable` | 代理被判不可用 |
| `request_failed` | 请求最终失败，带 `error` 字段 |
| `runtime_initialization_failed` | 启动阶段失败（多半是 WARP） |

打开请求体转储（含对话内容，注意隐私）：

```json
"logging": { "level": "debug", "dump_request_bodies": true }
```
