## 2. 今晚做了什么

### 2.1 根因：线路其实没坏，是 Clash 在直连

- 运行态是 `mode=global` 且 `GLOBAL` 选择器 = `DIRECT`，所以经 `127.0.0.1:7897` 的一切流量都**直连**出去，规则链（`PROCESS-NAME,opencode*`、`DOMAIN-SUFFIX,opencode.ai` → `OpenCode专线`）根本不参与。这解释了“直连和走 Clash 结果完全一样”。
- 旧的 Instabox 订阅（26 个 `pg-*` trojan 节点）已失效：TCP 443 可连但 TLS 握手 EOF / 502，服务器域名在本机 fake-ip DNS 下解析成 `198.18.0.11`。不要再切回 `RhdSiqhAbB79`。

## 3. 结论更正（重要）

- **不是额度耗尽**：同一套代码、同一 `Bearer public` 凭据，`o2a-fra` 能 200；本机网关经 WARP 轮换后也能 200。
- **不是身份问题**：`warpchat` 每次随机 `x-opencode-project`(40 hex) + `x-opencode-session`(`ses_`+64hex) 仍然 429。
- **是出口 `/64` 池部分脏**：上游对 free 模型按出口块限流。本机注册到的不少 `2a09:bac5:*` / `2a09:bac1:*` `/64` 已被烧，返回 `FreeUsageLimitError`，`Retry-After` 指向固定重置点（近期为次日 00:00 UTC）。网关的“首个 429 → `Report` + `Unbind` + 换 session/出口”策略能找到干净块，所以 200 与 429 交替出现是正常现象。
- **节点 IP 直打上游也是 429**：经 7897 直接 `POST https://opencode.ai/inference/openai/v1/chat/completions`，`Retry-After≈73807`。所以**不要**把 `config.json.proxies` 改成裸节点地址，必须保留 `warp.enabled=true` 让 WARP 出口轮换。
- `crouton-alpha-free`、`inkling-2-small-free` 的 403 是 `RegionError: This model is not available in your country`，与封禁无关。
