## 2. 仍未解决

### P3：没有每出口并发上限

同一 `/64` 可以被任意多个并发请求同时占用。并发高时一个出口先 429，整池跟着冷却。当前靠 `pool_size` 分摊，没有 in-flight 预算。

- 影响：突发并发下出口寿命短、429 集中
- 现状：`Acquire` 只保证租约独占，不限制同时在途请求数
- 建议方向：给 `exit` 加计数器或信号量，超过阈值就排队或换出口

### P4：429 分类是启发式

`classifyPenalty()` 只读状态码和响应体关键词。上游文案变化、项目级 RPM/TPM 限速、或网关层限速都可能被误判：

- 命中 `quota` / `usage limit` / `额度` / `billing` 等 → 额度型（长期冷却）
- 命中 `rate_limit` / `too many requests` → 普通限速（短冷却）
- **无法识别时默认额度型**，避免把已耗尽的 `/64` 当瞬时限速，代价是可能过度冷却

项目级限速换 IP 并不能解决；这种情况需要看上游响应体或账号维度，而不是继续烧池子。

### P5：可观测性不足

`/healthz` 的 `warp` 只有 `size / preload / active / standby / cooling`，没有：

- 每个 `/64` 的 429 次数、冷却剩余时间、存活时长
- 去重后仍可用的 `/64` 数量
- 每出口延迟、成功率

排障要翻 `logs\stdout.log` 的 `Rotating OpenCode WARP egress ... cooling ...`、`stays out of rotation`、`Discarding duplicate WARP exit` 等事件。

### P6：Linux 构建与部署路径未固化

`win/` 没有 `Dockerfile`；`iface_windows.go` 在 Linux 下是 no-op（这是设计），但：

- 直接拿 `win/` 构建 Linux 二进制可以编译（已验证 `GOOS=linux`），但没有容器编排与持久化目录约定
- Instacloud 上 `config.json` 若为只读挂载，`warp-state.json` 写不进去（现在会告警，但冷却记忆仍会丢）
- 需要为 `linux/` 单独建目录与基线，而不是把 `win/` 当部署目录

### 环境约束（不是代码 bug）

| 约束 | 表现 | 判断方法 |
|---|---|---|
| `api.cloudflareclient.com` 不可达 | WARP 注册失败，启动降级为直连/代理 | `curl --max-time 8 https://api.cloudflareclient.com/cdn-cgi/trace` |
| 到 WARP endpoint 的 UDP 2408 被拦 | 注册成功但握手 `handshake=never rx=0` | `warpprobe.exe` 或日志 `tx=... rx=0` |
| 设备凭据被 Cloudflare 丢弃 | 同样 `rx=0`，换网络也不恢复 | 删除 `config.json.warp-state.json` 后重新启用 WARP；仍失败则不是本地状态问题 |
| `/64` 供给有限 | `pool_size` 开再大也填不满，出现 duplicate 注册 | 日志 `Cannot replace ... duplicate`、`registration paused` |
| 物理网卡到不了 Cloudflare、只有 TUN 能到 | 钉选导致注册失败 | 临时 `set OPENCODE2API_WARP_NO_PIN=1` |
| 免费额度按 `/64` 计 | 同一 `/64` 换 `/128` 不加额度 | 池按 `/64` 去重，属预期 |

## 3. 仓库与进程层面的限制

| 限制 | 说明 |
|---|---|
| `config.json`、`usque/`、`tools/`、`*.exe`、`logs/` 不入库 | 含密钥、设备凭据或大二进制；恢复方式见 `08-备份与恢复.md` |
| `win/` 与主仓库同源但独立 | 不要在两边同时改同一份源码；上游同步用 `git fetch upstream main && git merge upstream/main` |
| 上游合并冲突 | `internal/gateway/runtime.go`、`webui/` 多个文件与上游重叠，合并时需手工校验 |
| 无自启动 | 重启后需要手动运行 `start-background.ps1` 或 `start-opencode2api.bat` |
| 单实例 | 同一份 `config.json` 不能同时起两个进程（端口、缓存、轮换状态冲突） |
| WebUI 只监听回环 | 默认 `127.0.0.1:28081`，不建议暴露公网 |

## 4. 怎么确认问题是否还在

```powershell
# 池状态与冷却数量
curl.exe --noproxy "*" http://127.0.0.1:28080/healthz

# 额度命中与冷却递增
Select-String -Path logs\stdout.log -Pattern "Rotating OpenCode WARP egress|stays out of rotation|inherited .* strike"

# 注册重复/限流
Select-String -Path logs\stdout.log -Pattern "duplicate|registration paused|replace"

# 状态文件
Get-Content config.json.warp-state.json -Raw
```

判据：

- 额度 429 后同一 `/64` 下一次应显示更长冷却（2h/8h/24h），而不是固定 30m
- 池空时日志应是 `stays out of rotation`，不是把该出口重新放回 `active`
- `preload` 应等于 `min(pool_size, 8)`；不等说明运行的二进制不是当前源码构建的
