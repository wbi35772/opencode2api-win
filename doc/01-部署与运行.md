# 部署与运行

## 环境要求

| 项目 | 要求 |
|---|---|
| 系统 | Windows 10/11 x64（本次在 Windows 11 x64 上验证） |
| Go | 1.24 及以上（`go.mod` 声明 `go 1.24`）；本次构建用 Go 1.27.3 |
| cgo | 不需要，构建时 `CGO_ENABLED=0` |
| 依赖 | 无，产物是单文件静态二进制 |

构建命令：

```powershell
cd win
$env:CGO_ENABLED = "0"
go build -trimpath -o opencode2api.exe ./cmd/opencode2api
go vet ./...
```

本次构建结果：

```text
opencode2api.exe   20,448,256 字节（19.5 MB）
go vet ./...       exit 0
```

## 目录结构

```text
win/
  cmd/opencode2api/main.go        入口
  internal/                       网关、协议、模型、WARP、管理后台
  webui/                          管理界面（编译时嵌入二进制，不是外部文件）
  assets/                         静态资源
  config.json                     运行配置
  config.example.json             原始模板
  opencode2api.exe                二进制
  logs/                           日志和 PID
```

`webui/` 和 `assets/` 通过 `go:embed` 打进二进制，运行时不需要这些目录。删掉它们不影响已构建的 exe。

## 启动

前台（关闭窗口或 Ctrl+C 即整体退出）：

```powershell
.\start-opencode2api.ps1
```

或者双击 `start-opencode2api.bat`。两个入口都走 `start-supervised.ps1`：网关、`tools\edgeproxy.exe` 和当前控制台被放进同一个 Job Object，控制台一关，Job 句柄关闭，内核会把整棵进程树一起结束。实测关闭窗口后不再残留 `opencode2api.exe` / `edgeproxy.exe`，28080/28081/29090 端口全部释放，网卡、默认路由、DNS、防火墙配置与启动前一致（WARP 是进程内 netstack，不建 TUN、不改系统网络）。

后台（推荐长期运行，日志写文件）：

```powershell
.\start-background.ps1
```

后台脚本会做这些事：

1. 检查 `opencode2api.exe` 和 `config.json` 是否存在
2. 如果 `logs\pid.txt` 里的进程还活着，直接返回，不会起第二个实例
3. 从 `config.json` 解析端口，被占用就报错退出
4. `Start-Process` 隐藏窗口启动，stdout/stderr 重定向到 `logs\`
5. 轮询 `/healthz`，最多 15 秒

注意：脚本以 **API 端口有响应** 作为启动成功判据，`ready:false` 不会判定失败。免费额度耗尽时健康检查会显示 `no_healthy_proxies`，但进程和 WebUI 是正常的。

## 停止

```powershell
.\stop-opencode2api.ps1
```

停止脚本对两种模式都有效：先按 `logs\pid.txt` 停后台网关，再按可执行文件路径清理本目录下的 `opencode2api.exe` 和 `tools\edgeproxy.exe`（不会误杀同名但位于其他目录的进程）。

前台模式直接关闭控制台窗口即可，Job Object 会一并回收网关和边缘代理；不需要再手动 `taskkill`。

## 端口与凭据

| 项目 | 值 | 修改方式 |
|---|---|---|
| API | `127.0.0.1:28080` | `config.listen` |
| WebUI | `127.0.0.1:28081` | `config.webui.listen` |
| API Key | `sk-win-local-test` | `config.server_keys` |
| WebUI 用户名 | `admin` | `config.webui.username` |
| WebUI 密码 | `win-admin-2026` | 登录后在界面改，或改 `config.webui.password` |

只监听回环地址，局域网访问不到。要对外提供，把 `listen` 改成 `0.0.0.0:28080` 并在防火墙放行；WebUI 不建议暴露。

## 命令行参数

| 参数 | 说明 |
|---|---|
| `-config <path>` | 配置文件路径，默认当前目录的 `config.json` |
| `-listen <addr>` | 覆盖 `config.listen` |
| `-web-listen <addr>` | 覆盖 `config.webui.listen` |

## 运行期生成的文件

服务运行时会往 `config.json` 同目录写状态缓存，这些都是自动生成的，删掉只会让下次启动重新拉取：

| 文件 | 内容 |
|---|---|
| `config.json.bak` | 每次保存配置前的备份 |
| `config.json.models.catalog.json` | 模型目录缓存，断网时用来兜底 |
| `config.json.<hash>.availability.json` | 模型能力探测结果（是否支持工具、思考等级） |
| `config.json.rotation.json` | 轮换组的运行状态 |

`logs\` 里：

| 文件 | 内容 |
|---|---|
| `stdout.log` | 结构化 JSON 日志 |
| `stderr.log` | 启动失败等错误 |
| `pid.txt` | 后台进程 PID |

## 构建产物说明

- `opencode2api.exe` 是静态二进制，不需要 Go 环境和 DLL
- 换机器直接拷 `opencode2api.exe` + `config.json` 即可运行
- WebUI 密码在第一次用明文 `password` 启动时会被转成 Argon2id 哈希写回配置，明文随后被清除
