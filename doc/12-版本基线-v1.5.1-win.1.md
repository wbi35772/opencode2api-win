### 2.2 安全与流式硬化（e2b2a7c 子集，全部生效）

| 项 | 行为 |
|---|---|
| 代理/WARP 重定向 | `CheckRedirect` 返回 `ErrUseLastResponse`，防止 `x-api-key` 与请求体被重放到重定向目标 |
| 错误脱敏 | `SecretRedactor` 改为单次 `strings.Replacer`；上游错误体、`Retry-After` 也脱敏；短 Key（≤5 字符）显示时哈希 |
| SSE 帧校验 | 只转发完整 SSE 帧；单帧上限 16 MiB；畸形/超长/未结束帧不转发；上游错误帧替换为通用失败 |
| 首帧状态 | `deferredStreamWriter` 在收到首个 SSE 帧前不提交 200；无效前奏返回 502 |
| 非流式响应 | 响应体上限 64 MiB |
| 工具名还原 | 重命名键包含 `choiceIndex`，避免跨 choice 错误消费工具名 |

### 2.3 客户端环境隔离（8f691a0，全部生效）

- Chat `system`/`developer`、Anthropic `system`、Responses `instructions`/`input`、Codex `<environment_context>` 中的环境声明都会被解析。
- 也接受顶层 `client_environment`：`working_directory`、`workspace_root`、`platform`、`is_git_repo`。
- 限制：最大 4096 字节；拒绝控制字符、行分隔符和尖括号；冲突或畸形声明回退为 `unknown`。
- 网关不再把宿主机的 `D:\...`、`win32`、workspace、git 状态塞给客户端；`shell` 描述按客户端平台渲染，未知时使用通用措辞。
- 本仓库 `toolshape.go`、`opencode_prompt.go`、`client_environment.go` 与上游 v1.5.1 逐字节一致。

### 2.4 免费道工具描述 NBSP（6575c62，全部生效）

- 只改**客户端工具的顶层 description**：Chat 改 `function.description`，Anthropic/Responses 改 `description`。
- 参数 schema、追加的官方工具、工具名还原逻辑都不动；替换幂等。
- 目的：规避上游免费层对工具描述字面措辞的拒绝；上游提交说明称原始 DSH fixture 在生产默认返回 200。
- 本仓库 `renameAndCompleteTools` 已包含：`strings.ReplaceAll(description, " ", "\u00a0")`。

### 2.5 OAuth 重构（e2b2a7c，源码完整，但本机不使用）

- `internal/goauth` 已删除；改用 `internal/oauth`（discovery + client）。
- 配置字段：`go_oauth`、`zen_oauth`；旧 `go_subscription`/`zen_subscription` 仍可迁移读取，但冲突会报错。
- 新增管理接口与 WebUI OAuth 页面；catalog 记录 OAuth tier/pending 状态（cache schema v4）。
- 本机没有 Zen/Go Key，`anonymous=true`，因此 OAuth 代码只保证可编译、可回归，不参与免费道路由。

### 2.6 匿名默认值与批量代理管理（0d05fe9，源码完整）

- `config.example.json` 的 `anonymous` 现在是 `false`；**本机 `config.json` 显式 `anonymous=true`**，行为不变。
- 新增 `POST /api/proxies/check`、`ProxyCheckResult`、`ProxyConnectError`、`config.ValidateProxyEntry`；代理页支持批量粘贴、检查、勾选删除。
- 本机仍使用单条 `socks5://127.0.0.1:10808`，批量页可用但不影响路由。

## 3. 保留的 fork 能力（故意不跟随上游）

### 3.1 WARP 增强

上游 `internal/warp` 在 v1.4.8..v1.5.1 **没有改动**；本仓库保留自有实现（17 个文件 vs 上游 8 个）：

| 能力 | 说明 |
|---|---|
| `warp.socks_udp` | WireGuard 外层 UDP 走 SOCKS5 UDP ASSOCIATE（当前 `socks5://127.0.0.1:10808`） |
| `warp.tun` | 允许 WARP socket 跟随系统路由；Windows 默认仍钉物理网卡 |
| 24h 额度黑名单 | `warp-state.json` 持久化已耗尽 `/64`，重启不清零；当前继承 56 个 spent 块 |
| 注册前预检 | 新出口先探测是否已耗尽，避免拿 spent `/64` 消耗真实请求 |
| 会话亲和 | `AcquireFor`/`Unbind`，多轮对话固定出口，429 时解绑换出口 |
| 分级冷却 | 额度 24h；普通限流 1 分钟起、最多 5 分钟；传输故障 90 秒 |
| Windows 网卡钉扎 | 自动选物理网卡；`OPENCODE2API_WARP_NO_PIN=1` 可关闭 |

### 3.2 免费道与会话增强

- `runtime.GOOS` 不再参与客户端环境伪造，但会保留在 fork 的 shell 描述兜底中（上游未知平台时用通用描述）。
- 自定义 `warp.pool_size=32`、`preload=12`、`max_anonymous_exits=32`、`free_tier_block_seconds=120` 继续有效。
- 保留 `zz_*` 调试测试、Windows 启动脚本、`doc/09` 的 SOCKS5 UDP 基线。

### 3.3 明确不做的事

| 项 | 原因 |
|---|---|
| 删除 fork `internal/warp` 换成上游简化实现 | 会失去 SOCKS5 UDP、黑名单、预检、亲和；上游未改 WARP，没有对齐收益 |
| 启用 Zen/Go OAuth | 本机只用免费道，没有付费 Key |
| 把 `anonymous` 改成 `false` | 本机 `config.json` 显式 `true`，否则免费道不可用 |
| 恢复 `internal/goauth` | 已由 `internal/oauth` 取代，旧包无调用方 |
| 移植 `#167` Playground relay | 仍不影响请求路径；保留在“未解决”清单 |

```powershell
Get-Process opencode2api -ErrorAction SilentlyContinue | Stop-Process -Force
$ts = Get-Date -Format 'yyyyMMdd-HHmmss'
Copy-Item .\config.json.warp-state.json ".\config.json.warp-state.json.bak-$ts" -Force
Remove-Item .\config.json.warp-state.json -Force
.\start-background.ps1
```

> 重置会丢掉已学习的出口冷却记忆；只在确认池子里没有可用出口时做。正常 429 优先等 2–4 分钟让池子回血。

## 8. 已知问题与限制

1. **WARP 依赖本机 Clash 10808 的 TCP + UDP。** UDP ASSOCIATE 不通时 WARP 注册/握手失败；后台会自动重试，恢复后无需重启。
2. **免费额度不是无限。** 上游按 `project × 出口` 计；连续请求会快速消耗出口。`cooling` 增长是正常现象。
3. **预检 429 不等于永久不可用。** 实测同一 `/64` 的预检返回 429 后，换一个出口地址仍可 200；预检只是保守跳过。
4. **OAuth 未启用。** 源码完整，但本机没有 `zen_oauth`/`go_oauth`；`sota`/`sweet` 组不可用。
5. **`#167` 仍未移植。** Playground 诊断页不能把一次生成固定到单个 relay；真实会话不受影响。
6. **catalog 缓存 schema v4。** 旧 v3 缓存会被忽略并重新拉取，属正常升级。
7. **`listen` 当前是 `0.0.0.0`。** 不需要局域网访问时建议改回 `127.0.0.1`。
8. **发布提交。** 代码 `e092353`；tag `v1.5.1-win.1`（文档随 tag）；发布包与该 tag 对应。
