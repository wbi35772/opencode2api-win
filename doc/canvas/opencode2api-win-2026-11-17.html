使用边界

免费配额按出口烧

配额单位是 (project, 出口 /64)。一个成功请求消耗一个出口，池子约每 30–40 秒补一个；连续猛发仍会短时 429，等 2–4 分钟或重置状态文件即可。

一句话基线

源码对齐上游 v1.4.8，Windows 产物为 v1.4.8-win.1；匿名免费道在无任何账号 Key 的情况下完成极简、带 tools 非流式、带 tools 流式三类 200 验证。当前运行进程只依赖本机 Clash 7897 提供 TCP 注册与 SOCKS5 UDP 中继。

02今天的修复：三层叠加

同一个 429 背后有三层独立问题。只修一层，仍会在下一次请求里复现。下面的顺序按“先排除代码、再看出口、最后调容量”排列。

第 1 层 · 二进制

旧 exe 发送 clint_

旧进程 PID 27404 构建于 19:11，早于 #182。它把客户端工具名统一加上 clint_ 前缀，免费层直接回 429；无 tools 的极简请求反而可能 200，形成“200 / 429 混合”的假象。

处理：构建并部署 v1.4.8-win.1，确认二进制内 clint_=False、mcp_=True。

第 2 层 · 出口状态

WARP 状态里全是 spent 出口

config.json.warp-state.json 继承了 13–14 个已烧掉的 /64 冷却记录；池子只有 1 个出口时，同样的流式请求 429/96 秒。

处理：备份并重置状态文件，重新注册出口；后台恢复后 active 从 0 长到 4–8。

第 3 层 · 容量

池子太小、复用太慢

原配置 pool_size=16、max_anonymous_exits=0、free_tier_block_seconds=0，出口耗尽后补充慢。

处理：改为 32 / 32 / 120 秒；一个成功请求消耗一个出口，池子约每 30–40 秒补一个。

04免费道工作原理

匿名免费道不是“不带 Key 直连”这么简单。网关要同时处理工具名、会话身份、project 身份、出口 /64 和 WARP 池。任一环节错位，上游都会以 429 或空响应表现。

图 2 请求链路。注册 HTTPS 走 proxies[0]；WireGuard 外层 UDP 走 socks_udp；免费道每个请求绑定一个出口，429 时按会话/项目/出口顺序轮换。

请求生命周期（匿名道）

  1. 客户端带 sk-win-local-test 调 /v1/chat/completions；网关先解析模型是否在免费名单。
  2. 工具定义统一改名为 mcp_*；legacy functions 只改名一次，避免二次前缀。
  3. title 请求预判：最多 1 次尝试，429/传输失败本地合成回退，不再拖垮主请求。
  4. 匿名道取一个 WARP 出口，按会话解析身份；同一会话固定出口，避免“新出口 + 旧会话”立即 429。
  5. 成功则记录出口；失败按图 1 轮换，保留最近上游 HTTP 错误与响应所有权。

免费配额为什么这么容易 429

  • 计量单位是 (project, 出口 /64)，不是单纯 IP；只换出口不换 project，会在新出口重放同一个 429。
  • 一个成功请求会消耗一个出口；池子补充速度约 30–40 秒/个，突发流量会先打穿现有出口。
  • 429 后出口默认退役 120 秒（本次配置）；`cooling` 是历史记录，`active=0` 才是当前无出口可用。
  • Clash 节点掉线时 WARP 握手 rx=0，免费道整体不可用；这不是额度问题，后台会按 15s→30s→1m→2m→5m 重试。

# 1. 看进程版本与池状态
curl.exe -sS --noproxy "*" http://127.0.0.1:28080/healthz

# 2. 看最近 WARP / 429 事件
Get-Content logs\run-v1.4.8-win.1-*.log -Tail 80 | Select-String 'WARP|429|Free usage|retry|fallback'

# 3. 备份并重置 WARP 状态（会重新注册出口）
Copy-Item config.json.warp-state.json "config.json.warp-state.json.bak-$(Get-Date -Format yyyyMMdd-HHmmss)" -Force
Remove-Item config.json.warp-state.json -Force
Get-Process opencode2api -ErrorAction SilentlyContinue | Stop-Process -Force
Start-Process -FilePath "$PWD\opencode2api.exe" -ArgumentList '-config',"$PWD\config.json" -WorkingDirectory $PWD
