# 备份与恢复

目标：任何时候都有一份**能拉下来、能编译、能跑**的版本，避免本机出问题后断掉唯一可用的免费通道。

## 1. 仓库拓扑

| 位置 | 内容 | 用途 |
|---|---|---|
| 主仓库 `jasonxu114514/opencode2api` | 上游源码，`v1.4.6`（`58f5667`） | 只读基线，不直接改 |
| `win/` 本地仓库 | Windows 二次开发版，含 WARP 补丁 | 日常开发与运行 |
| Forgejo `xiaoming/opencode2api-win` | `win/` 的完整历史 + 标签 + Release | 异地备份，可直接 clone |

Forgejo 地址（同一台机器上的 WSL x01）：

```text
http://wsl.x01:3005/xiaoming/opencode2api-win.git       ← 推荐，hosts 由 wslip 同步
http://172.30.196.173:3005/xiaoming/opencode2api-win.git
http://127.0.0.1:3005/xiaoming/opencode2api-win.git      ← 仅当 wslrelay 转发在运行
```

2026-11-01 实测：从 Windows 直接访问 `wsl.x01:3005` 与 `172.30.196.173:3005` 均返回 200；`127.0.0.1:3005` 在 WSL 重启后不可用（`localhostForwarding=false`，且 `wslrelay` 未常驻）。抓不到仓库时先换 `wsl.x01`。仓库是 **private**，拉取需要账号或访问令牌。

## 2. 哪些内容在仓库里

| 内容 | 是否入库 | 说明 |
|---|---|---|
| `cmd/`、`internal/`、`webui/`、`assets/` | 是 | 完整源码，可独立构建 |
| `doc/`、`README-WIN.md`、上游 README | 是 | 部署、配置、架构、问题、恢复文档 |
| `start-*.ps1`、`start-*.bat`、`stop-*.ps1` | 是 | 启动、监督、停止 |
| `config.example.json` | 是 | 配置模板（无密钥） |
| `go.mod`、`go.sum`、`LICENSE` | 是 | 构建依赖与许可证 |
| `config.json` | **否** | 含 Key、密码哈希、代理凭据，`.gitignore` 排除 |
| `config.json.*.json` | **否** | 运行期缓存与 WARP 状态，删了会重建 |
| `opencode2api.exe`、`*.exe.bak*` | **否** | 构建产物，走 Release 资产或现场编译 |
| `tools/`（含 `edgeproxy.exe`） | **否** | 本地工具，可选 |
| `usque/` | **否** | 含 WARP/MASQUE 私钥 |
| `logs/`、`config-backups/` | **否** | 运行日志与本地备份 |

因此"完整恢复"= 仓库里的源码/脚本/文档 + 本机另行保管的 `config.json`（或按模板重建）+ 可选的 `tools/edgeproxy.exe`。

## 3. 版本与标签

每次确认可用的版本都要打标签，并把二进制挂到 Release：

```powershell
git tag -a win-v1.4.6-warp-pool-20261101 -m "Windows build: upstream v1.4.6 + WARP penalty model"
git push origin main --tags
```

Release 资产包含：

- `opencode2api.exe`（可直接运行的 Windows 二进制）
- `SHA256SUMS.txt`（校验和）

下载后先核对：

```powershell
Get-FileHash .\opencode2api.exe -Algorithm SHA256
```

## 4. 恢复场景

### A. 本机可用，只想回到上一个版本

```powershell
cd D:\Project\Openchamber\Token\opencode\jasonxu114514-opencode2api\win
git fetch origin --tags
git log --oneline --decorate -20
git checkout <tag 或提交>
.\stop-opencode2api.ps1
```

如果该版本有 Release 资产，直接用资产里的 exe 覆盖，避免现场编译差异。

### B. 本机可用，但 exe 损坏或误删

```powershell
cd win
$env:CGO_ENABLED = "0"
go build -trimpath -o opencode2api.exe ./cmd/opencode2api
.\stop-opencode2api.ps1
.\start-background.ps1
```

或者从 Forgejo Release 下载 exe，校验 SHA256 后放入 `win\`。

### C. 换机器 / 本机重装

1. 安装 Git、Go 1.24+（`go.mod` 要求），确认 `CGO_ENABLED=0`
2. 克隆仓库：

   ```powershell
   git clone http://wsl.x01:3005/xiaoming/opencode2api-win.git
   cd opencode2api-win
   ```

3. 恢复 `config.json`（二选一）：
   - 从密码管理器/离线备份取回原文件；
   - 用 `config.example.json` 重建，至少改 `server_keys`、`webui.password`、`warp.enabled`、`proxies`
4. 可选：把 `tools\edgeproxy.exe` 放回；没有也能跑，只是 `proxies` 里的 `127.0.0.1:29090` 会不可用
5. 构建并启动：

   ```powershell
   $env:CGO_ENABLED = "0"
   go build -trimpath -o opencode2api.exe ./cmd/opencode2api
   .\start-background.ps1
   ```

6. 验证（见下一节）

### D. 只想要一个能立刻跑的二进制

从 Forgejo Release 下载 `opencode2api.exe` 和 `config.example.json`：

1. 放到任意目录
2. 复制 `config.example.json` 为 `config.json`，填入 Key 和 WebUI 密码
3. 运行 `.\opencode2api.exe -config .\config.json`

这是最小恢复路径，不需要 Go 环境。

## 5. 恢复后验证

```powershell
# 1. 进程与端口
Get-Process opencode2api,edgeproxy -ErrorAction SilentlyContinue

# 2. 健康检查（ready:true；WARP 开启时 warp.status:ready）
curl.exe --noproxy "*" http://127.0.0.1:28080/healthz

# 3. 带 Key 的模型列表（应返回 8 个免费模型）
curl.exe --noproxy "*" -H "Authorization: Bearer sk-local-test" `
  http://127.0.0.1:28080/v1/models

# 4. 一次真实对话
$body = '{"model":"deepseek-v4.1-flash-free","messages":[{"role":"user","content":"Reply with OK only."}],"max_tokens":16,"stream":false}'
[IO.File]::WriteAllText("$PWD\request.json", $body, (New-Object System.Text.UTF8Encoding($false)))
curl.exe --noproxy "*" -H "Authorization: Bearer sk-local-test" `
  -H "Content-Type: application/json" --data-binary "@$PWD\request.json" `
  http://127.0.0.1:28080/v1/chat/completions
```

成功判据：

- `/healthz` 返回 `status: ok`（`degraded` 且只有 `model_catalog_stale` 也可接受，等刷新）
- `/v1/models` 返回模型列表而不是 401
- 对话返回 `200` 且有内容，不是 `429 Free usage limit`
- `warp.preload` 等于 `min(pool_size, 8)`

## 6. 仓库完整性检查

```powershell
cd win
git fsck --full
git status --short          # 应为空
git remote -v               # origin → Forgejo，upstream → 主仓库
git tag -l "win-*"
```

如果 Forgejo 上的历史可疑，用本地仓库重新推送（本地历史是权威）：

```powershell
git push origin main --tags --force-with-lease
```

`--force-with-lease` 只在远端没有别人新提交时覆盖，不会误删其他人的工作。

推送凭证：仓库是 private，需要 Forgejo 用户名 `xiaoming` + 访问令牌（scope 至少 `write:repository`）。本机现成的令牌在 WSL 的 `~/.config/forgejo-opencode2api-win.token`（权限 600）；Windows 侧没有保存令牌，可以在 WSL 里推送：

```bash
cd /mnt/d/Project/Openchamber/Token/opencode/jasonxu114514-opencode2api/win
GIT_ASKPASS=<(printf '#!/bin/sh\ncat ~/.config/forgejo-opencode2api-win.token\n') git push origin main
```

或者给 Windows Git 配 `credential.helper=manager`，首次推送时输入令牌。

## 7. 日常规则

1. **改代码前先提交或打标签**，保证任意时刻有一个可回退点
2. **验证通过再打标签**，标签只代表"实测可跑"
3. **不提交 `config.json`**；它单独备份到密码管理器或离线介质
4. **每次换二进制前备份**：现有脚本/手工都保留 `opencode2api.exe.bak-*`
5. **恢复优先用 Release 资产**，现场编译作为后备；两者都要核对 SHA256
6. **WARP 状态可丢**：`config.json.warp-state.json` 删除后只会忘记冷却，不会损坏配置
